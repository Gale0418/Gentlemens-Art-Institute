# 條漫邊界點擊換書

> 歷史開發紀錄：下列測試數字與裝置狀態是當時的觀察，不代表最新版本已通過相同驗收。最新掃描維修紀錄見 [scan-progress-repair-2026-09-09.md](scan-progress-repair-2026-09-09.md)；未完成事項仍以任務中心追蹤。

使用者要求在條漫捲至最上／最下後，再點上方／下方區域，詢問是否開啟上／下一本。滑動本身不換書。

觸發區域為閱讀 viewport 上下各 20%，最多 180 CSS px；捲動邊界容許 2px 誤差。觸控與滑鼠／觸控筆皆要求起點與終點位於邊界，移動超過 12px、多指或取消手勢不觸發。點擊中間不開換書確認。

確認框顯示目標書名，提供「取消／開啟」，初始焦點在取消；Tab／Shift+Tab 留在對話框，Escape 取消。使用 App 內對話框，不依賴 WKWebView 的 JavaScript confirm handler。上下本以目前閱讀書籍為準，僅取相同來源及資料夾，依名稱自然排序；沒有鄰本時提示而不開確認框。關閉閱讀器、換書或確認期間鄰本變動，都會阻止過期操作。

驗證：完整 `npm test` 通過，包含實際註冊事件處理器的觸控與指標測試、單頁點擊保留、頂底／滑動／起終點邊界、取消與確認開書、過期確認、來源隔離，以及 pointerup 先於 touchend 的順序。日誌保存在 `output/release/2026-09-09-build6/frontend-tests.log`。第一輪 review 修正了跨模式誤擋點擊與測試僅檢查原始碼的不足。

macOS WKWebView 使用實際確認框函式與完整 CSS 驗證 393×852、820×1180：長書名換行、按鈕至少 44px、無水平溢出，焦點與取消／確認正常。補上底部安全區內距；macOS 的 safe-area 為 0；另以測試注入 34px 安全區，393×852 按鈕底端距螢幕底端為 59px。這是模擬安全區測試，仍需 iPhone 實機確認。
